= snake Manual

== Overview

The `snake` function, defined in `snake_func.sh`, renames files and directories to `snake_case`. It normalizes case, spaces, punctuation, periods, and brackets to produce consistent names across filesystems and tools.

The function can process a single path, the immediate entries of the current directory, or a directory tree. When a target name already exists, it can either generate a unique name with an `_N` suffix, replace an existing target file, or merge into an existing target directory.

== Requirements and Compatibility

* Bash 3.2 or later, or Zsh.
* Standard Unix utilities: `dirname`, `basename`, `sed`, `tr`, and `mv`.
* Source `snake_func.sh` from your shell configuration. See link:README.adoc[the README] for installation examples.
* On case-insensitive filesystems, such as the macOS default, case-only renames are recognized as the same file and do not receive an `_N` suffix.

== Usage

=== Syntax

[source,bash]
----
snake [OPTIONS] [path]
----

If `path` is omitted, or is `.` or `./`, the function processes entries in the current directory.

=== Options

[cols="1,1,3",options="header"]
|===
|Option |Long form |Description

|`-h`
|`--help`
|Show help and exit.

|`-r`
|`--recursive`
|Process directories recursively.

|`-p`
|`--period`
|Preserve periods instead of replacing them with underscores.

|`-o`
|`--overwrite`
|Overwrite an existing target instead of adding an `_N` suffix.
|===

=== Examples

[cols="1,2,2",options="header"]
|===
|Task |Command |Result

|Rename a file
|`snake "My File.txt"`
|`my_file.txt`

|Preserve periods in a name
|`snake -p "my.file.name.txt"`
|`my.file.name.txt`

|Process the current directory
|`snake .`
|Immediate entries are renamed.

|Process the current directory recursively
|`snake -r`
|Entries at every level are renamed.

|Rename a directory and its contents
|`snake -r "My Directory"`
|The directory and its contents are renamed.

|Overwrite an existing target
|`snake -o "My File.txt"`
|An existing `my_file.txt` is replaced.

|Replace brackets with underscores
|`snake "File [draft] (v2).txt"`
|`file_draft_v2.txt`

|Combine recursion, period preservation, and overwriting
|`snake -r -p -o "My.Directory"`
|The directory tree is renamed, periods are preserved, and collisions are overwritten.
|===

=== Current Directory Mode

When `path` is omitted, is `.`, or is `./`, the function processes the entries in the current directory instead of attempting to rename `.` itself.

Without `-r`, only immediate entries are processed. With `-r`, subdirectories are processed as well. An empty directory is a successful no-op.

=== Recursive Behavior

With `-r`, the function renames a directory if needed and then processes its contents, even when the directory name is already in snake_case. Without `-r`, a named directory is renamed but its contents are left untouched.

Active flags are propagated into recursive calls, so `-r -p -o` applies at every level.

=== Collisions and Overwrite Behavior

By default, `snake` does not silently replace an existing target. It appends an incrementing `_N` suffix instead.

[cols="2,2,2",options="header"]
|===
|Situation |Default |With `-o`

|Target file exists
|The suffix is inserted before the extension, for example `my_file_1.txt`.
|The existing target file is replaced.

|Target extensionless file exists
|The suffix is appended, for example `my_file_1`.
|The existing target file is replaced.

|Target directory exists
|The suffix is appended, for example `my_dir_1`.
|The source is moved into the existing target directory under its transformed name, for example `my_dir/my_dir`.

|Case-only rename on a case-insensitive filesystem
|The name is renamed without an `_N` suffix.
|The name is renamed without an `_N` suffix.
|===

Directories and files without a real extension keep the suffix at the end of the name. Files with an extension receive the suffix before the extension.

[CAUTION]
====
With `-o`, an existing target directory is not removed or replaced. The source is moved inside it under its transformed name. For example, `snake -o "My Dir"` when `my_dir/` already exists produces `my_dir/my_dir/`. If a directory with that transformed name already exists, the source is nested deeper using the same name, so the moved entry always keeps a snake_case name.
====

=== Period and Separator Handling

By default, periods are replaced with underscores, except for the period separating the filename from a real extension. Spaces, hyphens, punctuation, and brackets are treated as separators and become underscores.

Use `-p` or `--period` to preserve periods. Consecutive periods collapse to a single period, while spaces, hyphens, and brackets still become underscores.

[cols="2,2,2",options="header"]
|===
|Input |Default |With `-p`

|`subject.status.date`
|`subject_status_date`
|`subject.status.date`

|`this...is.my.file.txt`
|`this_is_my_file.txt`
|`this.is.my.file.txt`

|`My File.txt`
|`my_file.txt`
|`my_file.txt`

|`my-file.txt`
|`my_file.txt`
|`my_file.txt`

|`File [draft] (v2).txt`
|`file_draft_v2.txt`
|`file_draft_v2.txt`
|===

Extensions are always lowercased and normalized. Only a real, non-empty extension is split from the base name; files without an extension and names ending in a period are treated as a single base name.

== Design and Flow

NOTE: This section describes implementation details. Users only need the Usage and Exit Status sections.

=== Transform Pipeline

All character transformations are performed by the `snake_transform` function. The order is critical:

. **Convert to lowercase.** This makes the remaining comparisons and replacements consistent.
. **Replace spaces with underscores.**
. **Handle periods.** Replace them with underscores by default, or hide them behind a marker when `-p` preserves them.
. **Replace supported punctuation with underscores.** This includes commas, exclamation marks, pipes, and middle dots.
. **Handle brackets.** Replace square, round, curly, and angle brackets with a temporary marker, then convert the marker to underscores. When periods are preserved, remove bracket markers directly beside period markers first.
. **Replace hyphens with underscores.**
. **Remove apostrophes.**
. **Collapse repeated underscores.**
. **Restore preserved periods.** When `-p` is active, convert the period marker back to a period and collapse repeated periods.
. **Remove trailing non-alphanumeric characters.**

[IMPORTANT]
.Order of operations
====
The order matters because later steps create characters that earlier steps are supposed to normalize.

* **Convert first, collapse later.** Every step that can produce an underscore must run before underscores are collapsed. Spaces, rejected periods, punctuation, brackets, and hyphens all become underscores first. For example, `a-\_b` must become `a__b` before collapsing; if the collapse runs first, hyphen conversion leaves the double underscore behind. The same rule applies to any `_-\_`, `_._`, or similar mixed-separator cleanup: normalize the separators into their final form before merging adjacent ones.
* **Hide preserved periods before separator conversion.** With `-p`, periods must be replaced by a marker before underscores are introduced. Otherwise preserved periods would be handled as ordinary separators and could be converted to underscores.
* **Clean bracket markers beside preserved periods before brackets become underscores.** This prevents a bracket next to a preserved period from leaving a stray underscore on the other side of that period.
* **Collapse underscores before restoring periods.** The underscore step must complete while period markers are still distinct. Restoring periods first would expose `_._` and `_` runs beside periods to the wrong normalization.
* **Remove trailing non-alphanumeric characters last.** Trailing cleanup must follow underscore collapsing and period restoration, otherwise it can strip a separator that a later step would have merged or restored.
====

=== Filename Processing

* The directory path and filename are extracted first.
* A filename is split into base and extension only when it has a real, non-empty extension. Files without an extension, and names ending in a period, use the whole name as the base.
* The extension is always transformed with periods replaced and is lowercased.
* The base name is transformed with `snake_transform`, using the active period mode.
* The target name is rebuilt with the transformed base and, when present, the transformed extension.

=== Directory and Recursion Processing

* Directory names use the same transform as file base names. Periods are replaced unless `-p` is active.
* With `-r`, the directory is renamed first and then each entry is processed recursively.
* Current-directory mode iterates over the entries in the current directory rather than renaming the `.` path.
* Active flags are forwarded to recursive calls.

=== Adding New Transforms

All character transformations happen inside the `snake_transform` function. Each rule is a discrete Bash parameter-expansion substitution, which keeps new rules small and easy to read:

[source,bash]
----
# Separators become underscores
result="${result//@/_}"
result="${result//#/_}"

# Characters can be removed with an empty replacement
result="${result//;/}"

# Escape glob-special characters when matching them literally
result="${result//\[/_}"
----

The search pattern is a shell glob pattern, not a regular expression. Escape glob-special characters when they are meant literally, as the bracket rules do. This avoids the escaping and readability problems of regex-based replacements.

Placement is part of the transform:

. **Rules that produce underscores** must appear before `tr -s '_'` collapses underscore runs and before preserved periods are restored. Otherwise the new underscores will not merge with adjacent ones, and sequences such as `_-_`, `_._`, or repeated underscores may be normalized in the wrong order.
. **Rules that only delete characters** can sit with the other cleanup rules, but must still run before trailing character removal.
. **Rules that interact with preserved periods** must account for the period marker. Extend the marker handling deliberately instead of matching `.` directly.
